# Pussybreakers — учебный сайт

`index.html` — команда и задания 1–5, включая рецепты с учебными отзывами и профилями авторов. В шапке добавлена ссылка «Задание 6 · Люди» на новый каталог `users.html`. Прежние функции рецептов сохранены.

## Запуск

На этом Windows-компьютере достаточно открыть `START-SITE.cmd`: он запустит сервер в фоне и откроет каталог. Повторный запуск не создаёт второй сервер. Используется Python, уже установленный с Codex; на другом компьютере нужен Python 3 или VS Code Live Server. После перезагрузки компьютера запустите файл ещё раз.

Из папки сайта запустите:

```sh
python -m http.server 8000
```

На Windows также можно использовать `py -m http.server 8000`, на Linux/macOS — `python3 -m http.server 8000`. Откройте http://localhost:8000/ или http://localhost:8000/users.html. Подойдёт и VS Code Live Server. Нужен интернет для DummyJSON. Не открывайте `users.html` двойным щелчком через `file://`: браузер блокирует JS-модули.

Сайт написан на обычных HTML, CSS и JavaScript без сборки и библиотек. Node.js для запуска сайта не нужен. Рецепты теперь также используют JS-модули: открывайте обе страницы через HTTP-сервер, а не file://.

Для запуска нужны все папки, включая `ui/`. Скрипт `ui/boot.js` запускает модуль страницы и показывает понятную ошибку с кнопкой перезагрузки, если файл не загрузился. Ссылки на JS/CSS имеют общий номер версии, чтобы браузер не смешивал старые и новые файлы. Корзина подгружается отдельно: её ошибка не отключает каталог.

Код задания 5 находится в `recipes/app.js`. Запросы ограничены 15 секундами; после успеха или ошибки кнопки разблокируются. Повторное нажатие во время операции не отправляет второй запрос. Удаление в заданиях 5 и 6 подтверждается в окне внутри сайта (`ui/confirm.js`), которое не блокирует встроенный браузер системным `confirm()`.

## Отзывы к рецептам и профили авторов

В карточках блюд есть кнопка «Отзывы», а в окне рецепта под ингредиентами и шагами — отзывы с оценкой и карточкой автора. Нажатие на имя или аватар открывает профиль над рецептом; закрытие возвращает к тому же отзыву. Ссылка «Открыть в каталоге людей» ведёт на `users.html?user=ID` и автоматически открывает нужный профиль.

В DummyJSON у рецептов есть `rating` и `reviewCount`, но API не предоставляет тексты отзывов к рецептам: https://dummyjson.com/docs/recipes. `/comments` относится к публикациям (`postId`), а не к блюдам. Поэтому здесь **явно помеченные учебные тексты**, связанные с тестовыми профилями через `userId`. Примеры для первых 12 блюд находятся в `recipes/review-store.js`; число показанных примеров не выдаётся за серверный `reviewCount`.

Можно добавить учебный отзыв, выбрав тестового автора, оценку и текст. Это локальное действие без POST: сервис не имеет API отзывов к рецептам. Отзыв сохраняется при закрытии/открытии блюда и исчезает после перезагрузки. Форма не является авторизацией. Новые рецепты начинают без отзывов. Профили загружаются один раз с повторной попыткой при ошибке; их отображает та же `showProfile()`/`userCard()` из каталога. Модуль `recipes/reviews.js` соединяет отзывы с интерфейсом, `recipes/reviews.css` задаёт адаптивное оформление.

## Корзина блюд в профиле

Слева в профиле автоматически показывается заполненная корзина: 2–4 блюда с фотографиями и количеством порций. Справа — карточка человека и его данные. Это работает и при открытии автора отзыва, и в каталоге людей. Ничего выбирать или добавлять вручную не нужно. При ошибке загрузки доступна повторная попытка.

Это явно помеченные **учебные примеры**, автоматически составленные из рецептов. Набор зависит от `user.id`: у разных людей разные сочетания, а один профиль получает тот же набор при повторном открытии, перезагрузке и переходе между `index.html` и `users.html`, пока состав каталога рецептов не изменился. Нет localStorage, sessionStorage или БД.

DummyJSON Carts содержит **товары**, а не рецепты: https://dummyjson.com/docs/carts. Поэтому здесь отдельная учебная корзина блюд, а не подмена товаров по совпавшим ID. Каталог блюд получает `GET /recipes?limit=0&select=name,image` с таймаутом 15 секунд. У рецептов нет цены: интерфейс считает блюда и порции, не придумывая стоимость. POST/PUT/DELETE для корзины не отправляются. Общие модули: `recipes/cart-store.js`, `recipes/cart.js`, `recipes/cart.css`.

## Задание 6 — каталог людей

- Горизонтальные карточки с аватаром, именем, ником, ролью и ID.
- Большой профиль из двух половин: слева корзина блюд, справа та же карточка и подробные поля. На телефоне колонки располагаются друг под другом.
- Поиск по имени, фамилии и нику, сортировка имени в обе стороны, фильтр ролей: пользователь, модератор, админ.
- Создание, редактирование всех полей и роли, удаление с подтверждением.
- Проверка данных и уникальности ника без учёта регистра. Повторные запросы и закрытие формы блокируются на время операции.
- Ошибка не удаляет данные и не закрывает форму; начальную загрузку можно повторить. Фото при ошибке заменяется инициалами.
- Управление с клавиатуры, Escape и возврат фокуса после закрытия профиля/формы и удаления.
- Индикатор последнего HTTP-метода и кода ответа; для новых локальных профилей выводится «Локально».

### API и хранение

Документация: https://dummyjson.com/docs/users

| Действие | Запрос |
| --- | --- |
| Чтение | `GET /users?limit=0&select=firstName,lastName,username,image,email,phone,company,role` |
| Создание | `POST /users/add` |
| Изменение исходного человека | `PUT /users/{id}` |
| Удаление исходного человека | `DELETE /users/{id}` |

Базовый адрес — `https://dummyjson.com`, таймаут — 15 секунд. Проверяется `response.ok`; для DELETE дополнительно требуется `isDeleted === true`.

DummyJSON имитирует изменения, но не сохраняет их. После успеха изменяется единственный массив `app.users`, повторного GET нет. Перезагрузка возвращает исходные данные. Новым людям выдаются отрицательные ID −1, −2 и далее, независимо от ID в ответе POST. PUT/DELETE для этих записей не отправляются: они изменяются локально. Каталог не использует localStorage или БД. Существующее сохранение темы старых заданий остаётся в `index.html`.

Описание исходного человека собирается из должности, компании и отдела. В форме это редактируемый текст `description`. Пароли и банковские данные не загружаются в интерфейс и не включаются в запросы. Данные выводятся через `textContent` и `value`.

## Проверка

Node.js 22.7+; установка пакетов не нужна:

```sh
node --test tests/*.test.mjs
```

Автотесты API и правил данных подменяют fetch, не изменяя DummyJSON. Ручной сценарий: загрузить → найти по нику → сменить сортировку → проверить три роли → открыть карточку мышью и Enter → закрыть Escape → создать двух людей → изменить исходного и нового → отменить удаление → удалить обоих → перезагрузить. Проверяйте также отключённый интернет, ошибки запросов, узкий экран и сохранение фильтра после изменения роли.

## Перенос в существующий репозиторий

Скопируйте `index.html`, `users.html`, папки `users/`, `recipes/`, `ui/`, `tests/`, а также `README.md` и `package.json` из этой версии в корень вашего репозитория. Новая страница использует относительные пути и работает на GitHub Pages. Все файлы каталога должны быть загружены вместе; одного `users.html` недостаточно.
